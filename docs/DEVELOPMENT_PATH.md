# مسیر اصلی توسعه SMART — ۴ اکتبر ۲۰۲۶

آخرین اولویت‌های کاربر و موارد موکول‌شده به بعد: [فهرست کارهای ۱۳ اکتبر ۲۰۲۶](NEXT_WORK_2026-10-13.md).

هدف: تحلیل مستند و قابل بازپخش سهام بورس ایران. «بهترین تحلیل» باید با
نتیجه خارج از نمونه، پوشش داده و خطای اندازه‌گیری سنجیده شود؛ تعداد
اندیکاتورها یا تعداد استراتژی‌ها معیار کیفیت نیست.

## معماری مبنا

مسیر فعلی `smart.unified_analysis` مرجع هماهنگی است؛ موتور موازی جدید نسازید.

نماد → TSETMC/کدال → ذخیره خام → canonical → کنترل کیفیت → تکنیکال و
بنیادی مستقل → شواهد بازار/صنعت/جریان پول → آزمون خارج از نمونه → ریسک و
تصمیم قاعده‌مند → گزارش تغییرناپذیر → API/UI/MCP.

محاسبات داخل توابع مستقل از شبکه باقی بمانند. UI و مدل زبانی فقط مصرف‌کننده
خروجی هستند. مسیرهای قدیمی تا بررسی مصرف‌کنندگان و تست سازگاری حذف نشوند.

## ترتیب کوتاه‌ترین مسیر به نتیجه قابل اعتماد

| اولویت | کار | شرط پذیرش |
|---|---|---|
| P0 | صحت داده و تقویم، دوره کامل، توقف/بازگشایی، تازگی | داده آینده و کندل ناقص وارد تصمیم نشوند؛ خطا و حذف ردیف ثبت شود |
| P0 | تثبیت آزمون‌ها، کش مستقل، وضعیت صریح مراحل | تست‌ها بدون تکیه به کش کاربر تکرارپذیر باشند؛ ناقص هرگز کامل نباشد |
| P1 | تعدیل قیمت با رویداد رسمی و واحد ریال | قیمت خام/تعدیل‌شده جدا؛ افزایش سرمایه و تقسیم سود با منبع؛ بدون منبع UNVERIFIED |
| P1 | پوشش بنیادی شرکت‌های هدف | پنج سال و ۱۲ تا ۲۰ فصل در صورت وجود؛ تاریخ انتشار، نسخه اصلاحی، واحد و سلول منبع برای هر عدد |
| P1 | تکمیل تحلیل صنعت‌محور | شرکت تولیدی، بانک، سرمایه‌گذاری و صندوق قواعد مستقل داشته باشند؛ NAV صندوق جای EPS شرکت قرار نگیرد |
| P2 | تثبیت خانواده محدود مدل‌ها | روند، شکست/بازآزمایی و بازگشت به میانگین؛ پارامترها از validation، نه test |
| P2 | سنجش خارج از نمونه | train/validation/test زمانی، هزینه، لغزش، محدودیت نقدشوندگی و مقایسه با نگهداری سهم |
| P3 | پایش روزانه و انتشار | تصمیم ذخیره‌شده تغییر نکند؛ نتیجه آینده جدا ثبت شود؛ تغییر مدل فقط پس از ارزیابی |

ابتدا یک سبد ثابت و کوچک از نمادهای چند صنعت را به سطح پذیرش برسانید؛ سپس
پوشش را گسترش دهید. دریافت مجدد همه تاریخچه و اجرای همه پژوهش‌ها در هر کلیک
ضروری نیست: دریافت افزایشی و کش مبتنی بر داده/نسخه/تنظیمات حفظ شود.

## قواعد مهندسی

- Python 3.12 مبنای CI است. وابستگی اصلی در `pyproject.toml` ثبت شود؛ تا
  یکپارچه‌سازی نصب Docker، `requirements.txt` نیز باید با آن همگام بماند.
- کد جدید یا تغییرکرده type hint، قرارداد خروجی، خطای قابل ردیابی و تست
  رفتار داشته باشد. بازآرایی کل مخزن صرفاً برای ظاهر یا lint انجام نشود.
- هر تغییر عددی: مثال با جواب معلوم، مرز کمبود داده، و تست ثبات پیشوند در
  برابر اضافه‌شدن داده آینده. برای بنیادی، انتشار پس از تاریخ تصمیم ممنوع.
- هیچ مقدار گمشده‌ای با صفر یا امتیاز خنثی جایگزین نشود. کیفیت/کامل‌بودن
  داده از جذابیت سرمایه‌گذاری و اطمینان مدل جدا گزارش شود.
- تغییر تقویم یا قواعد عددی نسخه موتور و کلید کش را عوض کند. گزارش‌های
  قدیمی بازنویسی نشوند؛ ادعای قابلیت بازپخش فقط با نسخه متناظر مجاز است.
- CI تست، داده پژوهشی تولید و به مخزن push نکند. پژوهش سنگین در گردش کار
  مستقل اجرا شود. تست زنده منبع باید صریح و اختیاری باشد.
- حذف کد فقط پس از جست‌وجوی وابستگی و بررسی نقش آن؛ کد سالمی که کاربر دارد
  به دلیل شباهت نام‌ها حذف نشود.

## اقدامات این نوبت

- اصلاح مرز هفته در موتور ساختار تکنیکال به شنبه؛ نسخه TECH-STRUCTURE-2.
- جلوگیری از نمایش موفقیت برای وضعیت نامشخص/ناکافی مرحله؛ نسخه تحلیل ۲٫۴.
- مستقل‌کردن کش پژوهش تست‌ها از داده کاربر.
- جداسازی CI تست از اجرای پژوهش و commit خودکار؛ نصب از metadata بسته.
- افزودن وابستگی جاافتاده persiantools به نصب requirements/Docker.
- حذف سه تولیدکننده قدیمی تست که ارجاع فعال ندارند و فایل تست را بازنویسی
  می‌کنند: `fix_pipeline_e2e.py`، `fix_pipeline_e2e_no_subprocess.py`،
  `generate_test.py`. تست اصلی موجود حفظ می‌شود.

## هنوز تأیید نشده

کامل‌بودن بنیادی پنج‌ساله همه نمادها، تعدیل رویدادهای شرکتی، قابلیت اجرای
معامله در صف، برتری آماری مدل و بازده آینده تأیید نشده‌اند. استانداردسازی
این نوبت گواهی کیفیت تمام الگوریتم‌های قدیمی یا تضمین سودآوری نیست.

انجام نشده است.
