# مرحلهٔ ۲: دروازهٔ کیفیت داده — ۲۰۲۶-۰۹-۲۷

`smart.data_quality_gate` پیش از نتیجهٔ فنی، کندل‌های تاریخچه را بررسی می‌کند:
کندل آخر، حداقل تعداد نمونه، تاریخ آینده، تاریخ تکراری، OHLC ناقص یا ناسازگار،
حجم، تازگی و هش ردیف‌های معتبر. کندل بی‌معامله حذف/پر نمی‌شود؛ تاریخش در
گزارش کیفیت می‌ماند. وقتی آخرین داده نامعتبر یا قدیمی است، سطح ورود جاری
برگردانده نمی‌شود. نبود تاریخچهٔ تعدیل مستقل با `UNVERIFIED` ثبت می‌شود؛ کیفیت
فقط با وجود کندل خوب به `HIGH` ارتقا نمی‌یابد.

دروازهٔ کدال پیش از امتیازدهی، شناسه و دورهٔ جدیدترین سند، حسابرسی، وضعیت
همگام‌سازی، HTTP 429 و تعداد سال‌های موجود را ثبت می‌کند. تاریخ انتشار جلالی
تا زمان پیاده‌سازی و راستی‌آزمایی تبدیل تقویم، `publication_calendar_unverified`
دارد. این مورد **تکمیل‌شده محسوب نمی‌شود** و برای بازپخش تاریخیِ معتبر باید در
مرحلهٔ ۶ برش زمانی انتشار تکمیل شود. سند دارای تاریخ میلادیِ آینده `INVALID`
می‌شود و مانع بنیادی وابسته است.

قالب metric منبع‌گزارش‌شده، `calculated=false` و شناسه/تاریخ/واحد منبع دارد؛
metric محاسبه‌شده، `calculated=true` و فرمول و ورودی‌های تاریخ‌دار را نگه می‌دارد.
این قالب برای توسعهٔ شاخص‌های مراحل بعدی آماده است؛ هنوز ادعا نمی‌کند همهٔ
متریک‌های قدیمی مهاجرت کرده‌اند.

**آزمون هدفمند:** دادهٔ بی‌معامله، تکرار تاریخ، کندل آخر نامعتبر، تاریخ آینده،
تازگی منبع، تاریخ انتشار جلالی، ۴۲۹ و تمایز مشاهده/محاسبه.
